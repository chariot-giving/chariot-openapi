Listen for all three events emitted by Chariot Connect.

| Event | When it fires | Detail |
| --- | --- | --- |
| `CHARIOT_INIT` | The component is initialized and ready | None |
| `CHARIOT_SUCCESS` | The donor authorized the request | `OnSuccessMetadata` |
| `CHARIOT_EXIT` | The donor exited, an error occurred, or an unintegrated intent was confirmed | `OnExitMetadata` |

```javascript
const chariot = document.getElementById("chariot");

chariot.addEventListener("CHARIOT_INIT", () => {
  // The component is ready. Enable your DAFpay button.
});

chariot.addEventListener("CHARIOT_SUCCESS", ({ detail }) => {
  // Send the workflow session and returned amount to your server.
});

chariot.addEventListener("CHARIOT_EXIT", ({ detail }) => {
  // Handle the exact value in detail.reason.
});
```

A one-time success payload has this shape:

```json
{
  "workflowSessionId": "79e772be-547d-4c9c-8b76-4ac4ed4c441a",
  "grantIntent": {
    "fundId": "bbf485dd-a056-4a9d-89a8-06e201cdbf7f",
    "amount": 2000,
    "metadata": {}
  }
}
```

## On `CHARIOT_SUCCESS`

Save the relationship between:

- your transaction ID;
- `detail.workflowSessionId`;
- the Connect ID; and
- your nonprofit account.

Use the amount returned by DAFpay. The donor may have changed it inside the DAFpay window.

Save your transaction before calling Chariot. Show a loading state while your server creates the Grant. Do not show the final confirmation until Create Grant succeeds or the request has entered a durable retry process.

After the Grant is created, tell the donor that their grant request was submitted to their DAF provider. Do not say that your organization received the money.

## On `CHARIOT_EXIT`

Use the exact value in `detail.reason`:

| Reason | Meaning |
| --- | --- |
| `USER_EXIT` | The donor left the flow. |
| `UNINTEGRATED_DAF` | The selected provider is not integrated with DAFpay. |
| `UNINTEGRATED_GRANT_CONFIRMED` | The donor confirmed an unintegrated Grant. This is not a completed gift. |
| `UNINTEGRATED_DAF_NOT_SUPPORTED` | The selected provider does not support the unintegrated Grant flow. |
| `CID_NOT_FOUND` | The Connect ID was not found. |
| `SERVICE_DEACTIVATED` | The nonprofit's Connect is inactive. |
| `INELIGIBLE_ORGANIZATION` | The organization cannot receive DAF Grants. |
| `EIN_NOT_FOUND` | The provider does not support Grants to the nonprofit. |
| `CREDENTIALS_ERROR` | The provider credentials are invalid. |
| `TFA_ERROR` | Two-factor authentication failed. |
| `ACCESS_RESTRICTED` | Electronic access to the provider account is restricted. |
| `NO_CHARITABLE_ACCOUNTS` | The signed-in account has no charitable accounts. |
| `INVALID_PRESELECTED_DAF` | The supplied `fundId` is invalid. |
| `INVALID_CARD` | The card number is invalid. |
| `INACTIVE_CARD` | The card is inactive. |
| `ZERO_AMOUNT` | The Grant amount is zero. |
| `RECURRING_NOT_SUPPORTED` | The provider does not support recurring Grants. |
| `CONNECTION_FAILED` | The connection to the provider failed. |
| `INSTITUTION_DOWN_ERROR` | The provider is unavailable. The donor should try again later. |
| `SESSION_NOT_FOUND` | The session was not found or has expired. |
| `CUSTOM_ERROR` | A custom integration error occurred. |
| `INTERNAL_ERROR` | An internal error occurred. |

Treat an unrecognized reason as an error, not a completed gift.

In general:

- return a donor who closed the window to the form;
- ask the donor to restart an expired session;
- offer another payment method when the grant cannot be made; and
- log configuration and internal errors with the workflow session ID.

## Unintegrated Grants

An Unintegrated Grant records a donor's intent to give through a DAF provider that DAFpay cannot connect to directly. It is created with an `unknown` status and does not represent a completed gift.

When the donor confirms the intent, `CHARIOT_EXIT` fires with the reason `UNINTEGRATED_GRANT_CONFIRMED`. Use the [List Unintegrated Grants API](/api/unintegrated-grants/list) to retrieve the amount, DAF provider, donor details, tracking ID, and status.

By default, DAFpay waits for the donor to close its confirmation screen before sending the event. You can configure DAFpay to close the window and send the event immediately after confirmation.

Enable this option only after your confirmation page shows the tracking ID with its `Tracking ID:` prefix and a copy control, your organization name and EIN, and a link to the provider. Make clear that the donor must still complete the gift in the provider's portal.

## Recurring requests

A recurring success contains `recurringGrantIntent` instead of `grantIntent`. Send that distinction to your server so it can call Create Recurring Grant.
