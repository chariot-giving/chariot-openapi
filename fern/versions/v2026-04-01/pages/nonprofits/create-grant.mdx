After `CHARIOT_SUCCESS`, call Create Grant from your server. The browser flow alone does not create a grant.

<EndpointRequestSnippet endpoint="POST /v1/grants" />

## Server-side sequence

<Steps>

### Receive the session and amount

Take the `workflowSessionId` and the amount returned by DAFpay.

### Look up the transaction

Find the transaction and nonprofit you associated with that session.

### Save your transaction

Save it before creating the grant.

### Call Create Grant

Use your server-side API key, sent as a bearer token. See [Authentication](/api/authentication).

### Store the returned grant ID

### Retrieve the donation ID

Use [Get Grant](/api/grants/get) to retrieve the donation ID when it becomes available.

</Steps>

<Warning>
Create the grant promptly. The authorization expires 15 minutes after the donor completes DAFpay.
</Warning>

## Idempotency and retries

Create Grant is idempotent for a `workflowSessionId`:

| Response | Meaning |
| --- | --- |
| `201 Created` | This request created the grant. |
| `200 OK` | The session had already created a grant and the existing grant was returned. |
| `409 Conflict` | Creation is still in progress. Wait, then retrieve the grant. |
| `410 Gone` | The authorization expired. The donor must restart DAFpay. |

Do not retry blindly with a new workflow session.

## Amounts

Use the amount from `CHARIOT_SUCCESS`, not a stale amount from your form. DAF grants must be whole-dollar amounts, so cents must be divisible by 100. A Grant carries no currency field — grant amounts are US dollars.

### Provider limits

Create Grant can also return `400 Bad Request` when the amount is below the
provider's minimum or above the donor's available DAF balance.

**Minimum.** Once you have the `fundId` — from preselecting it, or after the
donor chooses — pass it to [Get DAF](/api/donor-advised-funds/get) and read
`minimumGrantAmount`. If the amount is short, tell the donor the figure they
need: "this provider requires a minimum grant of $50" recovers the gift where a
generic failure loses it.

**Balance.** The DAF carries no balance field, so you cannot check this before
you call. Treat the `400` as the signal, and offer the donor the choice of
lowering the amount or using another provider.

**Availability.** The same Get DAF response carries `institutionDown`. Handle a
provider that is down as a temporary error worth retrying, not as a failed
gift.

If `CHARIOT_SUCCESS` contains a recurring intent, use [Create Recurring Grant](/api/recurring-grants/create) instead of Create Grant.
