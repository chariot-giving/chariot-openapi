The FDX API uses Chariot's OAuth 2.0. The authorization code flow, token exchange, refresh, and redirect URI rules are documented in the [OAuth guide](/guides/oauth). Two things are specific to FDX: the scope you request and IP whitelisting.

## Scopes

The FDX API is read-only. Request the [`read_only` scope](/guides/oauth#scopes):

```
&scope=read_only
```

## Environments

Each environment has its own client name and secret — staging credentials cannot be used in production and vice versa. Contact Chariot at [support@givechariot.com](mailto:support@givechariot.com) to request credentials for each environment.

The [OAuth guide](/guides/oauth#authorization-code-flow) documents the production endpoints. Their staging equivalents:

| Endpoint | Staging |
|----------|---------|
| Authorization | `https://staging.dashboard.givechariot.com/oauth/authorize` |
| Token | `https://devapi.givechariot.com/auth/oauth/token` |
| OIDC configuration | `https://devapi.givechariot.com/.well-known/openid-configuration` |

## IP Whitelisting

In addition to OAuth 2.0, all requests are validated against an IP whitelist. Requests from non-whitelisted IP addresses receive a `403 Forbidden` response.

Contact Chariot to register IP addresses for FDX API access.
