The Chariot FDX API implements the [Financial Data Exchange (FDX)](https://financialdataexchange.org/) v6 standard, providing read-only access to bank account data for authorized financial data aggregators.

## Overview

The FDX API exposes 7 read-only endpoints organized around deposit accounts:

| Category | Endpoints | Description |
|----------|-----------|-------------|
| **Accounts** | List accounts, Get account, Get contact | Account information, balances, and contact details |
| **Statements** | List statements, Get statement document | Statement metadata and document downloads (PDF, CSV, BAI2) |
| **Customers** | List customers | Organization identity associated with an account |
| **Transactions** | List transactions | Transaction history with pagination and date filtering |

## Base URL

| Environment | Base URL |
|-------------|----------|
| **Production** | `https://api.givechariot.com/fdx/v6` |
| **Sandbox** | `https://sandboxapi.givechariot.com/fdx/v6` |

## Authentication

The FDX API uses Chariot's OAuth 2.0 — see the [OAuth guide](/guides/oauth) for the authorization code flow, token exchange, refresh, and the [environment endpoints](/guides/oauth#environments). For FDX:

| | Value |
|---|-------|
| **Scope** | [`read_only`](/guides/oauth#scopes) — the FDX API is read-only |
| **Credentials** | A client name and secret per environment, from [support@givechariot.com](mailto:support@givechariot.com) |
| **IP whitelisting** | Required. Your addresses must be registered before any request succeeds — see [IP Whitelisting](/guides/oauth#ip-whitelisting) |

Pass the access token as a Bearer token:

```
Authorization: Bearer <access_token>
```

## Key Concepts

### Pagination

List endpoints support cursor-based pagination using `pageKey` (a UUID cursor) and `limit` (10–100 results per page). The response includes a `page` object with `nextPageKey` when more results are available.

### Date Filtering

The statements and transactions endpoints support date range filtering via `startTime` and `endTime` query parameters (format: `YYYY-MM-DD`). Both must be specified together or both omitted. When omitted, defaults to the last 7 days.

Data is available for up to **24 months** from the current date. Requests with a `startTime` older than 24 months will return data starting from the 24-month boundary.

### Content Negotiation

The statement document endpoint supports multiple formats via the `Accept` header:

- `application/pdf` (default)
- `text/csv`
- `application/vnd.bai2`

### Error Format

All errors follow the [RFC 7807](https://www.rfc-editor.org/rfc/rfc7807) Problem Details standard with content type `application/problem+json`:

```json
{
  "type": "about:blank",
  "title": "Unauthorized",
  "status": 401,
  "detail": "Missing or invalid Bearer token"
}
```

| Status | Condition |
|--------|-----------|
| `400 Bad Request` | Invalid query parameters or missing required fields |
| `401 Unauthorized` | Missing, invalid, or expired Bearer token |
| `403 Forbidden` | Insufficient permissions or IP not whitelisted |
| `404 Not Found` | Resource does not exist (e.g., invalid account or statement ID) |
| `500 Internal Server Error` | Unexpected server error |
