Store Chariot identifiers as soon as they become available.

| Identifier | Source | Use |
| --- | --- | --- |
| Your transaction ID | Your platform | Primary key in your system. |
| Nonprofit ID | Your platform | Identifies the intended recipient. |
| Connect ID | Nonprofit onboarding | Confirms which nonprofit's Connect opened. |
| `workflowSessionId` | `CHARIOT_SUCCESS` | Ties the browser session to grant creation. |
| Grant ID | Create Grant | Stable Chariot grant identifier. |
| Donation ID | Grant or donation data | Links the request to Chariot's gift record. |
| Tracking or external grant ID | Grant data | Helps operations match provider remittance. |

Use your transaction ID, Chariot Grant ID, and Donation ID as durable keys. Treat human-readable tracking identifiers as reconciliation aids, not database keys; they may be absent or provider-dependent.

## How the funds arrive

DAFpay does not handle the funds. Each DAF provider pays the nonprofit directly, by transfer or mailed check, and stamps the payment with identifiers that can be matched back to the grant.

To show the provider's name, pass the grant's `fundId` to [Get DAF](/api/donor-advised-funds/get).

Before launch, document which Grant statuses are billable, which date controls an invoice period, how cancellations or adjustments are handled, and how grant-level reconciliation is delivered. These rules come from your Chariot agreement and operating plan; do not infer them from a single API status.

Expose the relevant identifiers to your support team and, where appropriate, nonprofit users. This lets them match a platform transaction to Chariot and provider records without searching by donor name and amount.
