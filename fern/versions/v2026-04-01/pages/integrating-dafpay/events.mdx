| Event | Meaning | Required action |
| --- | --- | --- |
| `CHARIOT_INIT` | The component is ready. | Update the page state if needed. |
| `CHARIOT_SUCCESS` | The donor authorized a one-time or recurring grant request. | Persist the session and create the grant from your server. |
| `CHARIOT_EXIT` | The donor left or DAFpay could not complete the flow. | Handle the returned reason. |

```javascript
const chariot = document.getElementById("chariot")

chariot.addEventListener("CHARIOT_SUCCESS", ({ detail }) => {
  // Persist detail.workflowSessionId with your transaction, then create the grant.
})

chariot.addEventListener("CHARIOT_EXIT", ({ detail }) => {
  // Handle detail.reason.
})
```

## On `CHARIOT_SUCCESS`

Associate the `workflowSessionId` with your transaction, nonprofit, and Connect ID. Use the returned amount, which may differ from the amount originally passed by the form.

```
your transaction ── nonprofit_id ── connect_id ── workflowSessionId
```

Persist your transaction before calling Chariot. Show a loading state while your server creates the Grant. Do not display success until that request succeeds or you have placed it into a recoverable retry flow.

The confirmation page should say that the request was submitted to the donor's DAF provider. Do not say the gift was processed, the nonprofit received the funds, or that the donor will receive another charitable tax receipt for the DAF grant.

## On `CHARIOT_EXIT`

Use the exact exit-reason enum from the component contract. Group the UI behavior by action:

- resume the form after a normal donor exit;
- restart an expired session;
- retry authentication or provider access when appropriate;
- offer another payment method when the grant cannot be made; and
- log configuration or internal failures with the workflow session ID.

An unsupported-provider confirmation is not a completed grant. Follow [Unconnected DAF providers](/guides/dafpay/integrating-dafpay/unintegrated).
