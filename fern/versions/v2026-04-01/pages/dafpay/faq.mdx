## Connects and Architecture

<AccordionGroup>

<Accordion title="**How many Connects does our platform need?**">
One per nonprofit. Store each Connect ID on the corresponding tenant record.
</Accordion>

<Accordion title="**When should we create a Connect?**">
When the nonprofit enables DAFpay. Do not create it during donor checkout. Backfill existing nonprofits using a restartable batch job.
</Accordion>

<Accordion title="**Can the Connect ID appear in browser code?**">
Yes. The Connect ID initializes the component. The API key must remain on your server.
</Accordion>

<Accordion title="**Where do we get API keys?**">
Nonprofits create their own sandbox and production keys in the Chariot dashboard. Fundraising platforms request keys from Chariot.
</Accordion>

<Accordion title="**Does the nonprofit need a Chariot account?**">
Yes. A nonprofit needs a Chariot account before you can create its Connect. Send nonprofits that do not have one to your co-branded Chariot onboarding link.
</Accordion>

</AccordionGroup>

## Checkout and Grant Creation

<AccordionGroup>

<Accordion title="**What does `CHARIOT_SUCCESS` mean?**">
The donor authorized the DAF request. Your server must still create the Grant. It does not mean the nonprofit received the money.
</Accordion>

<Accordion title="**Can a donor change their donation amount in the modal?**">
Yes, for three reasons:

1. Donors who can see their fund balance often choose to give more.
2. Some DAF providers set a minimum grant amount.
3. The amount cannot exceed the fund balance.

Use the amount returned by `CHARIOT_SUCCESS` when you call Create Grant, not the amount your form collected.
</Accordion>

<Accordion title="**Can we force DAFpay to open as a modal or a popup?**">
Chariot chooses between a modal on your page and a popup window based on the donor's browser and where the button sits. The `context` attribute on the element overrides that, but we do not recommend it. Forcing `iframe` can break the checkout in Safari, on mobile devices, and in embedded forms, and in `iframe` mode the modal only covers the frame the button renders in, so a button inside a tall iframe can leave the checkout partly off screen.

If you have a case where the default does not work, talk to us before overriding it.
</Accordion>

<Accordion title="**Why is DAFpay blocked on some mobile browsers?**">
Browsers may block a popup that opens too long after the donor's click. Prefetch data and keep all work between the click and DAFpay opening under one second.
</Accordion>

<Accordion title="**What if Create Grant times out or returns `410`?**">
If Create Grant times out, retry with the same `workflowSessionId`. Never start a new session for a retry.

The donor's authorization expires 15 minutes after they give it. If a Grant was already created, the retry returns `200` with that Grant. If no Grant was created and the authorization has expired, the API returns `410`.

Keep the donor's transaction pending until you know which happened, and contact [integrations@givechariot.com](mailto:integrations@givechariot.com) if the result is still unclear.
</Accordion>

<Accordion title="**Can we add or correct metadata after the donor authorizes?**">
No. Metadata can only be set in the browser through `onDonationRequest`, and Create Grant has no metadata field. Pass string values: anything else comes back stringified when you read the Grant.
</Accordion>

</AccordionGroup>

## Fees

<AccordionGroup>

<Accordion title="**How can our platform collect its processing fee?**">
Pass `applicationFeeAmount` on [Create Grant](/api/grants/create). Create Grant validates it against a ceiling set for your fundraising application and returns a `400` above it. How the fee is collected is set in your Chariot agreement.
</Accordion>

<Accordion title="**Can we add an optional tip?**">
DAF giving cannot be used to give to a for-profit entity, which means tipping the fundraising platform is not allowed.

If a donor has selected DAFpay, you must suppress the option to add a tip.
</Accordion>

<Accordion title="**How can donors cover fees?**">
Add the fee to the amount before the donor opens DAFpay. Raising the amount also raises the fee, so solve for the final amount, round it down to a whole dollar, and compute the fee from that amount so it stays under the ceiling. If the donor changes the amount in DAFpay, drop the fee coverage or ask them to reconfirm, and send [Create Grant](/api/grants/create) the returned amount.
</Accordion>

</AccordionGroup>

## Receiving Funds

<AccordionGroup>

<Accordion title="**How do nonprofits receive the money?**">
It depends on the provider. Gifts from Chariot's disbursement partners arrive electronically in the nonprofit's Chariot account. Other providers pay the organization directly, by ACH or check, on their own schedule. [Flow of Funds](/guides/dafpay/accept/managing-gifts#flow-of-funds) compares the routes.

Either way DAFpay does not hold the funds. Authorizing a request, creating the Grant and receiving the money are three separate events.
</Accordion>

<Accordion title="**How do nonprofits match a payment to a specific gift?**">
A DAF payment often arrives weeks or months after the donor gave, with little to identify it. DAFpay records two identifiers to close that gap: the Tracking ID, generated by DAFpay and usually passed through in the grant note, and the External Grant ID, generated by the provider. Both are on the Grant, and both appear in the Chariot dashboard.

Match on the Tracking ID where you have it and fall back to the External Grant ID. [Flow of Funds](/guides/dafpay/accept/managing-gifts#flow-of-funds) shows what the remittances look like.
</Accordion>

</AccordionGroup>

## Recurring and Unintegrated Providers

<AccordionGroup>

<Accordion title="**Does Chariot manage recurring Grant schedules?**">
No. A recurring DAFpay gift records that the donor set the gift up monthly; Chariot does not create a Grant each month. The DAF provider runs the schedule, and a donor cancels by logging into their provider's portal, so Chariot does not learn about cancellations. Reconcile the later Donations individually.
</Accordion>

<Accordion title="**What is an unintegrated DAF provider?**">
A provider DAFpay cannot submit the request to directly. If the feature is enabled, the modal collects the amount and donor details so the nonprofit is notified in real time, and gives the donor a Tracking ID to include in the note when they complete the gift in their provider's portal.

The Grant is created as `Initiated`, which means the donor was given instructions, not that they submitted the recommendation. Listen for `unintegrated_grant.updated` and treat the gift as complete when the status reaches `Completed`. Many stay at `Initiated`.
</Accordion>

</AccordionGroup>

## Operations

<AccordionGroup>

<Accordion title="**Which identifiers should we store?**">
Store the platform transaction ID, workflow session ID, Connect ID, Grant ID, and Donation ID. Also store and expose `trackingId` and `externalGrantId` when present.
</Accordion>

<Accordion title="**Should we use webhooks?**">
Yes, when you need timely state changes. Verify signatures, process events idempotently, and keep a scheduled recovery process for important state. Webhooks are not plan-gated, but they need an API key, and nonprofits can create keys in the dashboard only on a plan that includes API key management.
</Accordion>

<Accordion title="**Can a completed DAF Grant be refunded?**">
DAF funds are controlled by the provider, not the donor. Whether a request can be canceled depends on the provider and how far it has progressed. Do not present a standard refund action.
</Accordion>

<Accordion title="**What do the Grant statuses mean?**">
`Initiated` means the request was submitted to the provider. `Completed` means receipt was confirmed: Chariot recorded the settlement, a connected source recorded the payment, or the nonprofit clicked **Received** in the dashboard. It returns to `Initiated` only if an offline settlement recorded for it is removed. `Canceled` means the donor canceled or the provider did not approve the Grant.
</Accordion>


<Accordion title="**How do we get from a Donation back to its Grant?**">
A Donation does not carry a grant ID. Call List Grants with `donation_id`, or match the Donation's `initiation.dafpay_tracking_id` to the Grant's `trackingId`. In the other direction, the Grant's `donationId` is filled in shortly after creation, so if it is empty, read the Grant again later.
</Accordion>

<Accordion title="**Can our platform mark a Grant received?**">
No. The nonprofit marks it Received in the Chariot dashboard, and your platform learns about it from `grant.updated`.
</Accordion>

<Accordion title="**Who handles what?**">
Your platform supports donors on your form and your nonprofits' setup. Chariot handles nonprofit onboarding and verification, payouts, and Grant issues, at [integrations@givechariot.com](mailto:integrations@givechariot.com). The DAF provider handles the donor's account and any cancellation.
</Accordion>

</AccordionGroup>
