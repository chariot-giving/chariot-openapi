Use `onDonationRequest` to pass information from your donation form to DAFpay. Register it on the element you installed, once the component has loaded:

```javascript
const chariot = document.getElementById("chariot");

chariot.onDonationRequest(async () => ({
  amount: 25000,
  firstName: "Michael",
  lastName: "Scott",
  email: "michael@example.org",
  designation: "Community programs",
  metadata: {
    formId: "form_123",
    campaignId: "spring-2026"
  }
}));
```

## Supported fields

| Field | Type | Notes |
| --- | --- | --- |
| `amount` | number | Amount in cents. Pass it when the donor selected an amount. If omitted, DAFpay may recommend an amount based on the available DAF balance. |
| `firstName` | string | Donor's first name. Maximum 255 characters. |
| `lastName` | string | Donor's last name. Maximum 255 characters. |
| `email` | string | Valid donor email. Maximum 255 characters. |
| `phone` | string | Include the country code and omit special characters. Maximum 255 characters. |
| `note` | string | Donor note to the nonprofit. Maximum 400 characters. |
| `anonymous` | boolean | Whether the donor requested anonymity. Defaults to `false`. |
| `designation` | string | Defaults to `Where needed most`. Truncated at 255 characters when the workflow session is created. Create Grant's own `designation` field caps at 100. |
| `address` | object | Contains `line1`, `line2`, `city`, `state`, and `postalCode`. |
| `metadata` | object | Name-value pairs associated with the workflow session. Metadata is visible in the Chariot dashboard but is not shared with DAF providers. |
| `lockAmount` | boolean | Prevents the donor from changing the amount inside DAFpay. Defaults to `false`. |
| `fundId` | string | Preselects a DAF provider and skips the provider picker. |
| `frequency` | string | `ONE_TIME` or `MONTHLY`. Defaults to `ONE_TIME`. |

<Note>
  DAF Grants must use whole-dollar amounts, so `amount` must be divisible by 100. The modal accepts a value that is not a whole dollar and Create Grant rejects it later, so validate before you open DAFpay.
</Note>

## What to pass in metadata

1. **Form identifiers:** Pass stable identifiers the nonprofit needs for CRM coding, such as campaign, appeal, designation, source, form, comment, dedication, and tribute data. You do not need to pass the page URL: Chariot records it on the Donation as `initiation.web_location_url`, including any tracking parameters already in it, such as a source or campaign code.
2. **Donor information:** For express checkout, you do not need to pass any donor information. When your Connect is set to return donor information, DAFpay fills in the donor's details from their DAF account after they sign in; otherwise it asks the donor for them. If your form collects donor details before showing the DAFpay button, pass them in `onDonationRequest` so the donor does not have to enter them twice.
3. **Purpose or designation:** You can pass the donor's designation in one of two places. In the top-level `designation` field, it is sent to the DAF provider with the Grant request, truncated at 100 characters, and it fixes the purpose on the Donation. Some providers review a restricted designation before releasing the Grant, which can slow the gift. In `metadata`, the request stays unrestricted: the Grant is initiated with a purpose of "Where needed most", and your designation shows up in the Chariot dashboard.
    1. If your form allows a donor to divide one gift among multiple designations, you can use a custom object in the metadata to specify the breakdown between the designations.

```javascript
{
  amount: 60000,
  designation: "Community programs and General fund",
  metadata: {
    allocations: '[{"designationId":"community","amount":30000},{"designationId":"general","amount":30000}]'
  }
}
```

## Prevent blocked popups

DAFpay must open in direct response to the donor's click. Keep the time between the click and the DAFpay window opening under one second.

Load required data and validate nonprofit eligibility before the click. Avoid network requests, donation-history lookups, and other slow work inside `onDonationRequest`.

Using an `async` callback is fine. The risk comes from waiting for slow work before it returns.

If your platform uses a custom button or Shadow DOM, do not call your server between the donor's click and triggering DAFpay. Complete the request first, then let the click open DAFpay immediately.

## Disable DAFpay from opening when the form is not ready

If your donation form has required fields, disable the DAFpay button until the form passes validation. Keep your own form validation and error messages alongside it, so the donor can see what to fix.

Setting the `disabled` attribute on the element will prevent the modal from launching.

```javascript
const chariot = document.getElementById("chariot");

function syncDafpayAvailability() {
  const amount = getAmountInCents();
  const ready = Number.isInteger(amount) && amount > 0 && amount % 100 === 0;
  chariot.toggleAttribute("disabled", !ready);
}
```
