Use this checklist as a roadmap while you build, and complete it before requesting production access.

Everything in the first four sections applies to every integration. If you are a fundraising platform offering DAFpay across many nonprofits' forms, also work through [the platform section](#if-you-serve-many-nonprofits) at the end.

## Decide

- [ ] Choose donor-detail, recurring, and unintegrated-provider behavior.
- [ ] Decide which forms and campaign types include DAFpay, and confirm donors can see that DAFpay is available before completing the full form.
- [ ] Decide whether DAFpay gifts sync to your CRM, and how hard and soft credit work.
- [ ] Decide whether a donor may cover the fee.

## Build

- [ ] Load the supported Chariot Connect package.
- [ ] Initialize it with the right Connect ID.
- [ ] Keep the API key on your server.
- [ ] Apply the required CSP directives.
- [ ] Send current form data through `onDonationRequest`.
- [ ] Omit unknown donor fields instead of sending empty strings.
- [ ] Pass stable attribution and transaction identifiers.
- [ ] Handle all Chariot Connect events.
- [ ] Write loading, success, and exit copy.
- [ ] Save your transaction before calling Create Grant.
- [ ] Make Create Grant idempotent and complete it within 15 minutes.
- [ ] Route recurring intents to Create Recurring Grant, and do not retry it on a `409`.
- [ ] Implement the selected unintegrated-provider behavior.
- [ ] Store workflow session, Grant, Donation, tracking, and external Grant identifiers.
- [ ] Subscribe to the events you need and verify signatures against the raw body.
- [ ] Add a scheduled recovery query for events your endpoint misses.

## Validate

- [ ] Repeat Create Grant for one workflow session and confirm only one Grant exists.
- [ ] Simulate completed and canceled Grants and confirm your handlers respond.
- [ ] Complete the donor flow on every supported browser and device.
- [ ] Confirm DAFpay opens within one second of the donor's click, including with popups blocked.
- [ ] Verify the exact metadata returned from multiple form types.
- [ ] Deliver the same event twice and confirm it does not create a second record.
- [ ] Confirm support users can search the reconciliation identifiers.
- [ ] Confirm unintegrated-provider and recurring behavior when enabled.

## Launch

- [ ] Complete Chariot's production review.
- [ ] Create production event subscriptions.
- [ ] Give support access to your own and Chariot's identifiers.
- [ ] Plan a live production gift and a 30-day post-launch review.

## If you serve many nonprofits

These tasks exist because one integration serves many Chariot accounts. A nonprofit integrating its own donation form can skip them: Chariot provisions your Connects, so there is no tenant routing to get wrong.

### Decide

- [ ] Define how new and existing nonprofits enable DAFpay.
- [ ] Follow the opt-in, default-on, or other enablement rule in your Chariot agreement.
- [ ] Confirm whether DAFpay may appear before a nonprofit claims its Chariot account.
- [ ] Decide whether the platform charges an application fee.
- [ ] Document whether a nonprofit enables DAFpay once or per form.

### Build

- [ ] Search for each nonprofit by EIN.
- [ ] Create one Connect per nonprofit and store it on the correct tenant record.
- [ ] Use a nonprofit-specific contact email, not your support address.
- [ ] Load the Connect ID from the same nonprofit record that owns the form.
- [ ] Leave DAFpay unavailable when a nonprofit has no enabled Connect.
- [ ] Write unclaimed-account and missing-EIN copy.
- [ ] Display Tracking IDs and External Grant IDs on the nonprofit's dashboard, searchable and easy to copy.

### Validate

- [ ] Test two nonprofits concurrently and confirm tenant routing.
- [ ] Confirm each Grant belongs to the intended nonprofit.
- [ ] Confirm nonprofit users can find and match their own gifts.

### Launch

- [ ] Publish clear nonprofit setup instructions.
- [ ] Distribute the co-branded Chariot onboarding link.
- [ ] Name the nonprofit participating in production validation.
