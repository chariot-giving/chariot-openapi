Rather than polling, you can subscribe to events and have Chariot notify your endpoint when something changes. Create a subscription with the Create Event Subscription endpoint. Each subscription carries exactly one category.

Webhooks are not plan-gated, but nonprofits need a plan with API key management to create the key.

<EndpointRequestSnippet endpoint="POST /v1/event_subscriptions" />

## Events

| Event | Who can subscribe | When it fires |
| --- | --- | --- |
| `grant.created` | Platforms, and nonprofits for Grants on their own Connect | A DAFpay Grant was created. Fires only for DAFpay. |
| `grant.updated` | Platforms, and nonprofits for Grants on their own Connect | A Grant changed, including a status change. |
| `unintegrated_grant.created` | Platforms | An Unintegrated Grant was recorded. |
| `unintegrated_grant.updated` | Platforms | An Unintegrated Grant changed. |
| `donation.created` | Nonprofits | A Donation was created, from DAFpay or from any other payment source. |
| `donation.updated` | Nonprofits | A Donation changed, including gaining a settlement. Assigning a property also fires it. |
| `deposit.created` | Nonprofits | An inbound transfer to your Chariot account was recorded. Settlement arrives as `deposit.updated`. |
| `deposit.updated` | Nonprofits | A Deposit changed, including its settlement status. |

Donations and Deposits are scoped to an organization. A platform API key is bound to a fundraising application rather than to an organization, so a platform can create a subscription to those categories and it will never deliver.

We recommend building CRM sync on the donation events, so the same logic handles DAFpay gifts and gifts from your other payment sources. Use `grant.created` when you want a trigger that fires only for DAFpay.

## Recovering What You Miss

Keep a scheduled recovery query running alongside your webhooks. List Events returns past events, filters by `category`, and pages with the `cursor` parameter and the returned `nextPageToken`. Run recovered events through the same processing path as live deliveries.

See [Webhooks and Events](/api/webhooks) for signature verification, what an event contains, retries, and handling duplicate deliveries.
