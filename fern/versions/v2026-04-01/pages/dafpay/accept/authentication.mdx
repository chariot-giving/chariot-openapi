Server-side calls authenticate with an API key passed as a bearer token.

```text
Authorization: Bearer <API_KEY>
```

Sandbox and production are separate environments with separate keys, separate Connects, and separate data. Create each key yourself in the Chariot dashboard.

| Environment | Base URL |
| --- | --- |
| Sandbox | `https://sandboxapi.givechariot.com` |
| Production | `https://api.givechariot.com` |

Sandbox Connect IDs begin with `test_` and production Connect IDs begin with `live_`.

Configure the base URL, the API key, and the Connect ID together, as one set per environment. Mixing them is the most common setup error, and a sandbox key against the production host fails in ways that look like a permissions problem.

## Where each credential belongs

The Connect ID appears in your page's HTML, because the browser needs it to render DAFpay. That is expected and safe.

The API key must never reach the browser. Every call that uses it, including Create Grant, runs from your server.

## Sandbox

No real funds move in sandbox. Every DAF provider in the list is a mock, and sandbox exposes simulations for completing and canceling a Grant, so you can exercise your received-funds handling without waiting on a provider. The test login and the rest of the test plan are on [Testing and QA](/guides/dafpay/accept/sandbox).
