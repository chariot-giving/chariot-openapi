---
title: "Merging donations"
subtitle: "Combine two donation records into one."
---

## What a merge does

You call merge with two donation IDs: `from` and `into`. Chariot keeps the `into` donation and its ID. It soft-deletes the `from` donation and points it at the `into` donation through `merged_into_donation_id`.

```json
POST /v1/donations/merge
{
  "from": "donation_to_merge_from",
  "into": "donation_to_keep"
}
```

The response is the `into` donation after the merge.

## How field values combine

A value already set on the `into` donation is kept. A value it is missing can be filled with the value from the `from` donation.

## What you see afterward

- `GET` on the `into` donation's ID returns it as usual.
- `GET` on the `from` donation's ID still returns it. It carries `deleted_at` and `merged_into_donation_id`.
- The list endpoint stops returning the `from` donation.
- A write to the `from` donation returns `409`. The error carries the `into` donation's ID, so you can retry against it.
- A `donation.deleted` webhook is fired for the `from` donation.
- A `donation.updated` webhook is fired for the `into` donation.

## A merge is permanent

You cannot undo a merge. Check both donations before you merge them.

## Errors and retries

- **Both donations are reconciled to a deposit.** The merge returns `409` with problem type `donation_merge_conflict`. Chariot cannot merge two settled gifts.
- **An input is already deleted or merged.** The merge returns `409` with problem type `donation_deleted` or `donation_merged`.
- **The same donation on both sides.** The merge returns `400`.
