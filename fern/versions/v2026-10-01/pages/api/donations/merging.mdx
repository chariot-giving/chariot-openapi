---
title: "Merging donations"
subtitle: "Combine two donation records into one."
---

## What a merge does

You call merge on the donation you want to keep. You pass the ID of the donation to merge in. Chariot keeps the donation at `{id}` and its ID. It soft-deletes the merged donation and points it at this donation through `canonical_donation_id`.

```json
POST /v1/donations/{id}/merge
{ "donation_id": "donation_to_merge_in" }
```

`{id}` is the donation record you'd like to keep. `donation_id` is the donation record you'd like to merge in. The response is this donation after the merge.

## How field values combine

A value already set on the donation at `{id}` is kept. A value it is missing can be filled with the value from the merged donation.

## What you see afterward

- `GET /v1/donations/{id}` returns this donation as usual.
- `GET` on the merged donation's ID still returns it. It carries `deleted_at` and `canonical_donation_id`.
- The list endpoint stops returning the merged donation.
- A write to the merged donation returns `404`. The error carries this donation's ID, so you can retry against it.
- Webhooks fire. This donation sends `donation.updated`. The merged donation sends `donation.deleted`.

## A merge is permanent

You cannot undo a merge. Check both donations before you merge them.

## Errors and retries

- **Both donations are reconciled to a deposit.** The merge returns `409` with problem type `donation_merge_conflict`. Chariot cannot merge two settled gifts.
- **An input is already deleted or merged.** The merge returns `404` with problem type `donation_deleted` or `donation_merged`.
- **The same donation on both sides.** The merge returns `400`.
- **A repeat.** Repeating a completed merge is safe. It returns `200` with this donation.
